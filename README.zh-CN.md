# Jira Git GUI

一个桌面工具，帮你做好两件日常事：

- **看 / 同步 Jira 上的 Git 仓库代码** —— 不用 clone 就能浏览文件，对比本地和远端的差异，再把远端改动合并回本地。
- **K8s 日常运维** —— 看日志、进容器敲命令、传文件、一键出巡检快照。

支持 macOS / Windows / Linux。同一套界面有三种打开方式：Electron 桌面应用、更轻量的 Tauri 应用，或直接在浏览器里用。

> English docs: [README.md](README.md)

## 你能用它做什么

| --- | --- |
| 浏览 Jira 仓库里的文件和代码 | 仓库 / 文件树 / 文件预览 |
| 按文件名找文件，或搜代码内容 | 文件树 → 搜索框 |
| 看某个目录最近谁改了什么 | 差异对比 → 最近更新 |
| 对比本地代码和远端差在哪 | 差异对比 |
| 把远端改动合并回本地 | 差异对比 → 合并 |
| 看历史某个提交里文件长什么样 | 差异对比 → 提交列表里点文件名 |
| 看 Pod 日志、排障 | K8s → 日志查看 |
| 进容器敲命令 | K8s → Shell |
| 从容器里下载 / 上传文件 | K8s → 文件 |
| 一键抓一批 Pod 的状态和日志 | K8s → 快照 |
| 查云函数日志 | 云函数日志 |

## 快速开始

### 方式一：用打包好的桌面应用（日常使用推荐）

装完即用，不需要装 Python。

| 平台 | 安装包 |
| --- | --- |
| macOS | `.dmg` |
| Windows | `.exe`（NSIS 安装包） |
| Linux | `.AppImage` / `.deb` |

> 安装包**未做签名**，首次打开会被 Gatekeeper / SmartScreen 拦下。macOS 在「系统设置 → 隐私与安全性」里放行，Windows 点「更多信息 → 仍要运行」。

### 方式二：一键脚本（本机从源码跑）

```bash
./scripts/run.sh              # 起后端并打开浏览器
./scripts/run.sh --electron   # 改为启动 Electron 桌面应用
```

### 方式三：手动启动

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=. ./venv/bin/python -m api.server      # 然后打开 http://127.0.0.1:8787
```

如果 `npm` 或 Electron 下载被网络卡住，直接跳过——起好后端，在任意浏览器打开 `http://127.0.0.1:8787/` 即可。这和桌面应用加载的是同一个页面。

### 第一次使用：连上 Jira

应用启动时会自动读项目根目录的 `.env`，所以一般配一次就够，之后不用再填「连接设置」：

| `.env` 键 | 含义 | 备注 |
| --- | --- | --- |
| `jira_url` | Jira 基础地址 | 也接受 `JIRA_URL` |
| `username` | 账号名 | PAT 模式下填 PAT 持有者的账号 |
| `mode` | `pat`（默认）或 `cookie` | 见下方说明 |
| `personal_access_token` | PAT | 也容忍旧拼写 `persoanl_access_token` |
| `cookie` | 会话 Cookie | 格式：`JSESSIONID=...; atlassian.xsrf.token=...` |

`.env` 已被 gitignore —— **请勿提交真实凭据**。真实环境变量（如 `JIRA_URL`）优先于 `.env`。

**两种模式怎么选？**

- **PAT** —— 把仓库 clone 到本地。最可靠，支持文件历史和各种文件类型，需要一个 personal access token。
- **Cookie** —— 通过 Jira 网页抓取。不用 clone，拿不到 PAT 时很方便。代价：少数大文件 / 二进制只能走兜底通道，且 Cookie 过期后浏览会失效，需要重新刷新。

## 使用流程

### 浏览仓库

1. 在**仓库**标签页选一个仓库。下拉里显示「仓库名 · ID」，同名仓库也能区分开。
2. **文件树**随即加载 —— 展开目录，或直接粘贴完整路径跳过去。
3. 点文件即可预览。

要搜索就用文件树的搜索框：可以按文件名搜，也可以搜文件内容。

### 把远端改动同步到本地

这是最核心的流程 —— 可以理解成「给一个只能通过网页访问的仓库用 git」。

1. 打开**差异对比**标签页。
2. 选**对比仓库**，再选**对比目录**（手动输入路径，或从文件树里挑）。只扫一个子目录会快很多。
3. **快速扫描**保持开启。它只比对文件大小、不下载内容 —— 在大仓库上这是「几秒」和「几分钟」的差别。
4. 点**扫描**。你会拿到一份清单：已修改 / 仅远端有 / 仅本地有 / 仅行尾差异，并且带上以往合并留下的**已合并 ✓** 徽标。
5. 单文件点**合并**，或直接批量合并。进度实时推送。
6. 重复合并是安全的：已经一致的文件会被跳过，只重新拉取过期的部分。如果你改过本地文件，它会重新同步，而不是被悄悄跳过。

几个值得知道的附加能力：

- **最近更新** —— git log 风格列出该目录的近期提交。
- **导出报告** —— 把扫描 + 合并结果写成 Markdown，便于归档或贴进 Jira 评论。
- **勾选合并** —— 在文件树里勾几个文件，只合这一批。
- **历史版本** —— 在提交列表里点文件名，查看那一版内容，并与本地对比。
- **冲突保护** —— 如果上次同步后你改了、远端也改了同一个文件，应用不会直接覆盖，而是停下来让你选：保留本地 / 采用远端 / 手动合并。

### K8s：看日志

1. **K8s** 标签页 → 选**环境**（dev / test / prod，带彩色标签）。
2. 打开**日志查看**，选 Pod 和容器。
3. 可以搜索（支持正则）、按级别高亮、选择 tail 行数、开实时刷新，或下载成 `.txt`。

还有一个**全屏日志页** —— 从快照页（⧉）或 Shell 里打开，可以同时盯多个 Pod。

### K8s：进容器敲命令

**K8s → Shell** → 选环境、Pod、容器 → 连接。这是真终端：`vim`、`top`、`less` 都能正常用，`cd` 之后目录会保持，↑/↓ 翻命令历史。

### K8s：传文件

**K8s → 文件** 像 FTP 客户端一样浏览容器文件系统：双击文本文件直接编辑并保存回写，支持上传、下载（大文件带断点续传和进度条）、新建目录、删除。

### K8s：巡检快照

**K8s → 快照** 会执行 `kubectl get pods`、逐个 Pod 抓日志、按 HIGH / MED / OK 分级，并输出一份自包含的 HTML 报告和 JSON 到 `~/k8s_snapshots/<时间戳>/`。适合快速过一遍「有没有东西挂了」，或者把证据附到工单上。

### K8s：环境与凭据

每个环境（dev / test / prod）各自维护 kubeconfig、context 和默认命名空间。

与其让 kubeconfig 散落在 `~/Downloads` 之类的地方，建议用**环境管理 → 导入 kubeconfig**：它会把文件收进受控目录 `~/.config/jira-git-gui/kubeconfigs/<env>.kubeconfig`，并自动设为 `600` 权限，只有你能读。

环境配置也支持导出，用于备份或共享 —— 但导出内容包含集群凭据，请只通过加密通道传递。

### 云函数日志

**云函数日志**标签页可以查询、过滤、排序、导出云函数日志，也能把结果直接复制成文件。

## 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 改了代码，界面却还是老的 | **硬刷新**（**Cmd/Ctrl+Shift+R**）。后端是按请求从磁盘读前端产物的，所以重新构建后刷新即可，不用重启。 |
| 提示「会话已失效」，或文件树一片空白 | Jira Cookie 过期了。更新 `.env` 里的 `cookie`，或改用 PAT 模式。 |
| 文件预览报「文件过大或为二进制」 | Cookie 模式下大文件 / 二进制属于预期情况。改从文件树里下载，或用 PAT 模式。 |
| 批量合并卡在大文件上 | 大文件 / 二进制现在会走插件原始文件端点合并。如果仍失败，请改用 PAT 模式。 |
| 文件显示「已修改」，但内容看着一样 | 通常是行尾差异。差异对比页默认勾选「忽略行尾差异」，取消勾选就能看到它们。 |
| 打包后的应用行为和源码不一致 | 冻结的后端是旧的，需要重建 —— 见下方「给开发者」。 |
| 同名仓库，本地目录自动填充填错了 | 已知问题：`.env` 的 `MERGE_REPO_*` 映射是按仓库**名**建立的。请用下拉里显示的 ID 选对仓库，并手动指定本地目录。 |

## 各标签页速览

- **仓库 / 文件树 / 文件预览** —— 选仓库、浏览、看代码。
- **提交记录** —— 按 Issue 或仓库查提交，带行级 diff。
- **差异对比** —— 上面那套对比与合并流程。
- **K8s** —— 快照 / Pod YAML / 描述 / 网络检测 / 事件流 / 资源 Top / Shell / 文件 / 日志查看。
- **云函数日志** —— 云函数日志查询与错误诊断。
- **日志** —— 应用自身的运行日志，出问题时看它。

浅色 / 深色主题切换在顶栏。

## 给开发者

```bash
# 前端
cd frontend/web-react && npm install
npm run build        # 含类型检查；必须用它，不要直接跑 `vite build`

# 测试
QT_QPA_PLATFORM=offscreen ./venv/bin/python -m pytest tests/ --basetemp=.pytest_tmp

# 重建桌面应用实际运行的冻结后端
./venv/bin/python build/build.py --flavor backend
```

> **重要**：桌面应用运行的是**冻结后端**（`dist/jira-git-backend`）。改完 `core/` 或 `api/` 下的任何东西，都必须重建它 —— 否则应用仍跑旧逻辑，哪怕你的源码已经是最新的。这个坑真实造成过「我明明修了却没生效」的困惑。

架构与模块划分见 **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)**，打包与发布见 **[docs/PACKAGING.md](docs/PACKAGING.md)**。

## 已知限制

- 安装包**未签名** —— 首次打开需要手动放行。
- **Cookie 模式能力弱于 PAT** —— 部分大文件 / 二进制要走兜底通道，会话过期后浏览会失效。
- **一个 Shell 标签页对应一条会话。** 断开即结束；想同时看多个，请用全屏日志页。
- **`.env` `MERGE_REPO_*` 按仓库名建立映射** —— 同名仓库会撞 key，这类仓库请手动指定本地目录。
- `main.py`、`gui/`、`workers/` 是较早的 PyQt6 桌面实现，仅作参考保留。发行版为 Electron + Tauri。
