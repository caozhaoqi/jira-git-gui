# Jira Git GUI

一个桌面工具，帮你做好两件日常事：

- **看 / 同步 Jira 上的 Git 仓库代码** —— 不用 clone 就能浏览文件，对比本地和远端的差异，再把远端改动合并回本地。
- **K8s 日常运维** —— 看日志、进容器敲命令、传文件、一键出巡检快照。

支持 macOS / Windows / Linux。同一套界面有三种打开方式：Electron 桌面应用、更轻量的 Tauri 应用，或直接在浏览器里用。

> English docs: [README.md](README.md)

## 你能用它做什么

| 你想做的事 | 去哪个标签页 |
| --- | --- |
| 浏览 Jira 仓库里的文件和代码 | 仓库 / 文件树 / 文件预览 |
| 按文件名找文件，或搜代码内容 | 文件树 → 搜索框 |
| 看某个目录最近谁改了什么 | 差异对比 → 最近更新 |
| 对比本地代码和远端差在哪 | 差异对比 |
| 把远端改动合并回本地 | 差异对比 → 合并 |
| 看历史某个提交里文件长什么样 | 差异对比 → 提交列表里点文件名 |
| 看 Pod 日志、排障 | K8s → 日志查看 |
| 进容器敲命令 | K8s → Shell |
| 从容器里下载 / 上传文件 | K8s → 文件 |
| 一键抓一批 Pod 的状态和日志 | K8s → 快照 |
| 查云函数日志 | 云函数日志 |
| 批量清理 HCM 的 Redis Key（带常用 Key 预设） | HCM 运维 → Redis |
| 看 HCM 线上接口报错（数量趋势 + 明细） | HCM 运维 → 线上错误 |
| 解密 HCM 接口抓包参数 | HCM 运维 → 参数解密 |
| 让外部 AI 助手直接读取各面板的实时输出 | AI 数据桥 |

## 快速开始

### 方式一：用打包好的桌面应用（日常使用推荐）

装完即用，不需要装 Python。

| 平台 | 安装包 |
| --- | --- |
| macOS | `.dmg` |
| Windows | `.exe`（NSIS 安装包） |
| Linux | `.AppImage` / `.deb` |

> 安装包**未做签名**，首次打开会被 Gatekeeper / SmartScreen 拦下。macOS 在「系统设置 → 隐私与安全性」里放行，Windows 点「更多信息 → 仍要运行」。

### 方式二：一键脚本（本机从源码跑）

```bash
./scripts/run_web.sh              # 起后端并打开浏览器
./scripts/run_web.sh --lan        # 允许局域网设备连接（需要启动令牌）
./scripts/run_web.sh --electron   # 改为启动 Electron 桌面应用
```

局域网模式会监听所有网卡，来自局域网设备的 API 请求需要每次启动时随机生成的令牌。其他设备打开 `http://<本机局域网IP>:8787` 后输入令牌即可；在运行服务的电脑上执行 `curl http://127.0.0.1:8787/api/auth/token` 获取令牌，只通过可信渠道分享。该模式使用明文 HTTP，只应在可信网络中使用（或放在 VPN/HTTPS 代理后）；同网段监听者可能截获登录令牌。

> 桌面端入口是 Electron / Tauri 安装包；从源码跑 Web 模式用 `run_web.sh` / `run_web.ps1`。
> PyQt6 桌面实现已于 2026-10 移至 `pyqt-legacy` 分支存档，主干不再包含。

### 方式三：手动启动

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=. ./venv/bin/python -m api.server      # 然后打开 http://127.0.0.1:8787
```

如果 `npm` 或 Electron 下载被网络卡住，直接跳过——起好后端，在任意浏览器打开 `http://127.0.0.1:8787/` 即可。这和桌面应用加载的是同一个页面。

### 第一次使用：连上 Jira

源码运行时会自动读取项目根目录的 `.env`（打包版读取用户数据目录）：

| `.env` 键 | 含义 | 备注 |
| --- | --- | --- |
| `jira_url` | Jira 基础地址 | 也接受 `JIRA_URL` |
| `username` | 账号名 | PAT 模式下填 PAT 持有者的账号 |
| `mode` | `pat`（默认）或 `cookie` | 见下方说明 |
| `personal_access_token` | PAT | 也容忍旧拼写 `persoanl_access_token` |
| `cookie` | 会话 Cookie | 格式：`JSESSIONID=...; atlassian.xsrf.token=...` |

`.env` 已被 gitignore —— **请勿提交真实凭据**。PAT 和 Cookie 首次读取时会迁移到操作系统凭据存储（macOS 钥匙串、Windows 凭据管理器/DPAPI、Linux Secret Service）；真实环境变量（如 `JIRA_URL`）优先于 `.env`。

**两种模式怎么选？**

- **PAT** —— 把仓库 clone 到本地。最可靠，支持文件历史和各种文件类型，需要一个 personal access token。
- **Cookie** —— 通过 Jira 网页抓取。不用 clone，拿不到 PAT 时很方便。代价：少数大文件 / 二进制只能走兜底通道，且 Cookie 过期后浏览会失效，需要重新刷新。

## 使用流程

### 浏览仓库

1. 在**仓库**标签页选一个仓库。下拉里显示「仓库名 · ID」，同名仓库也能区分开。
2. **文件树**随即加载 —— 展开目录，或直接粘贴完整路径跳过去。
3. 点文件即可预览。

要搜索就用文件树的搜索框：可以按文件名搜，也可以搜文件内容。

### 把远端改动同步到本地

这是最核心的流程 —— 可以理解成「给一个只能通过网页访问的仓库用 git」。

1. 打开**差异对比**标签页。
2. 选**对比仓库**，再选**对比目录**（手动输入路径，或从文件树里挑）。只扫一个子目录会快很多。
3. **快速扫描**保持开启。它只比对文件大小、不下载内容 —— 在大仓库上这是「几秒」和「几分钟」的差别。
4. 点**扫描**。你会拿到一份清单：已修改 / 仅远端有 / 仅本地有 / 仅行尾差异，并且带上以往合并留下的**已合并 ✓** 徽标。
5. 单文件点**合并**，或直接批量合并。进度实时推送。
6. 重复合并是安全的：已经一致的文件会被跳过，只重新拉取过期的部分。如果你改过本地文件，它会重新同步，而不是被悄悄跳过。

几个值得知道的附加能力：

- **最近更新** —— git log 风格列出该目录的近期提交。
- **导出报告** —— 把扫描 + 合并结果写成 Markdown，便于归档或贴进 Jira 评论。
- **勾选合并** —— 在文件树里勾几个文件，只合这一批。
- **历史版本** —— 在提交列表里点文件名，查看那一版内容，并与本地对比。
- **冲突保护** —— 如果上次同步后你改了、远端也改了同一个文件，应用不会直接覆盖，而是停下来让你选：保留本地 / 采用远端 / 手动合并。

### K8s：看日志

1. **K8s** 标签页 → 选**环境**（dev / test / prod，带彩色标签）。
2. 打开**日志查看**，选 Pod 和容器。
3. 可以搜索（支持正则）、按级别高亮、选择 tail 行数、开实时刷新，或下载成 `.txt`。

还有一个**全屏日志页** —— 从快照页（⧉）或 Shell 里打开，可以同时盯多个 Pod。

### K8s：进容器敲命令

**K8s → Shell** → 选环境、Pod、容器 → 连接。应用会申请 PTY，优先使用 `bash`、没有时回退到 `sh`；`cd` 和 ↑/↓ 命令历史可保持。`vim`、`top`、`less` 等全屏工具还要求容器内已安装该程序且 PTY 可用；若连接降级为行缓冲模式，则无法交互使用这些工具。

### K8s：传文件

**K8s → 文件** 像 FTP 客户端一样浏览容器文件系统：双击文本文件直接编辑并保存回写，支持上传、下载（大文件带断点续传和进度条）、新建目录、删除。

### K8s：巡检快照

**K8s → 快照** 会执行 `kubectl get pods`、逐个 Pod 抓日志、按 HIGH / MED / OK 分级，并输出一份自包含的 HTML 报告和 JSON 到 `~/k8s_snapshots/<时间戳>/`。适合快速过一遍「有没有东西挂了」，或者把证据附到工单上。

### K8s：环境与凭据

每个环境（dev / test / prod）各自维护 kubeconfig、context 和默认命名空间。

与其让 kubeconfig 散落在 `~/Downloads` 之类的地方，建议用**环境管理 → 导入 kubeconfig**：它会把文件收进受控目录 `~/.config/jira-git-gui/kubeconfigs/<env>.kubeconfig`，并自动设为 `600` 权限，只有你能读。

环境配置也支持导出，用于备份或共享 —— 但导出内容包含集群凭据，请只通过加密通道传递。

外部工具也可通过受本机 API token 保护的 `POST /api/k8s/env/incoming` 推送 kubeconfig。内容只暂存在后端内存中（最多 5 份、每份 1 MiB、30 分钟过期）；待导入列表不会返回凭据正文。打开 **K8s → 环境管理** 后，用户必须手动确认导入；若环境标识已存在，还会再次确认覆盖。取消或过期不会写入环境配置。

```bash
TOKEN=$(curl -fsS http://127.0.0.1:8787/api/auth/token)
jq -n --arg name "dev" --rawfile content "$HOME/.kube/config" \
  '{name:$name, content:$content}' |
  curl -fsS -X POST http://127.0.0.1:8787/api/k8s/env/incoming \
    -H "X-API-Token: $TOKEN" -H "Content-Type: application/json" --data-binary @-
```

### 云函数日志

**云函数日志**标签页可以查询、过滤、排序、导出云函数日志，也能把结果直接复制成文件。

### 云函数监控

**云函数监控**（侧栏「云函数」分组内）把这些日志按云函数聚合成一块运行状态看板，不用逐条翻日志就能看出「哪个函数在坏」：

- 顶部 KPI：云函数数 / 异常函数 / 错误条数 / 正常函数，右侧标注本次采样量与命中模型；
- 表格每行一个云函数：总数、错误数、错误率、健康度、最近活动时间、最近一条消息；
- 状态色条 + 健康度徽标只表达语义（异常=红、告警=黄、正常=绿），不铺满整行；
- 点异常行展开：错误码分布（如 `80002 × 56`）、执行阶段分布、**多种错误样本**（按语义去重，忽略 RID 等每条不同的前缀；点每条可展开完整 traceback，保留换行与缩进）；
- 「只看异常」即时过滤；抓取规模分快速/标准/深度（默认标准 = 1000 条 × 3 页，约 2~3 秒）；
- 支持自动刷新（15/30/60/300 秒），面板隐藏时自动暂停、切回前台补一轮。

环境下拉框只列出真实可用地址（测试残留的 `http://x` 之类占位会被过滤），并优先选中「有 token 且上次没报错」的环境；token 失效时给出重新登录指引，而不是干瘪报错。后端接口 `POST /api/cf/monitor` 与命令行工具共用同一套聚合规则。

### 云函数一致性

**云函数一致性**对本地云函数目录与线上部署版本做扫描比对，找出漂移的函数，避免「本地改了线上没发」或反向的不一致。

### HCM 接口

**HCM 接口**是一个通用 HCM 平台接口调试器：选接口、填参数、直接调用并查看原始返回，适合临时验证某个平台 API 的行为。

### HCM 对象

**HCM 对象**列出当前环境下全部对象模型，选中后在右侧查看字段、JSON 元数据，并在 **数据** 子页签查询记录。

**数据子页签支持两种视图**：

- **表格**（默认）—— 按字段对齐成表，记录多、字段多时便于横向对比；点列头排序；序号列吸附，横向滚动不丢行号；嵌套字段折叠成 `{n}` / `[n]`，点开看完整 JSON；空值统一显示 `—`；「复制表格」可直接粘贴进 Excel / 飞书。
- **JSON** —— 原始嵌套结构，适合单条记录逐层核对。

记录多到一屏放不下时，工具栏右侧提供：

- **全屏** —— 模态全屏查看，列多行多时最实用；同样支持「复制表格」。
- **新窗口** —— 独立窗口打开（可最大化、拖到另一块屏）。数据过大时无法写入会话存储，会提示改用全屏。


### HCM 运维

**HCM 运维**面向 HCM 平台的日常运维操作，目前包含三块：

- **Redis** —— 浏览/搜索 Redis Key、查看值，支持批量删除（删除前有二次确认）。内置常用 Key 预设（如 `cache.possible.key` 一类业务键模式），一键填入匹配串。
- **线上错误** —— 拉取 `monitor.error.get_error_list` 的线上接口报错，按时间/关键字过滤，快速定位最近异常。
- **参数解密** —— 把抓包得到的 HCM 接口加密参数还原成明文。用法：复制抓包请求的**完整响应体**，粘贴后解密。注意两层结构 —— 外层明文 body 里嵌套的 `hcm_param` 才是加密载荷，且解密需要带有效 token cookie（token 过期时应用会自动重登重试）。

### AI 数据桥

**AI 数据桥**把每个功能面板的实时输出暴露成本地 HTTP 接口，外部 AI 助手（Claude / 自建 Agent 等）可以直接拉取应用正在显示的数据，无需复制粘贴。

- 面板输出在产生时自动上报（默认关闭，在 AI 数据桥页打开开关；偏好存于 `jgg-ai-bridge`）。
- 每个面板保留最近 20 条输出、单条最大 256KB（超长截断）。
- 在任意面板右下角有 **AI API 悬浮按钮**，一键复制当前面板的 curl 命令。
- AI 输入是独立的默认关闭开关；开启后，外部 AI 只能把内容排队为草稿。用户点击“插入编辑器”后才会覆盖对应的 YAML、HCM 参数或 Kibana 搜索编辑框，不会自动保存、执行 `kubectl apply` 或发起查询。

本地 API 需要启动令牌。先在本机读取令牌，并在后续请求带上 `X-API-Token`：

```bash
TOKEN=$(curl -fsS http://127.0.0.1:8787/api/auth/token)

# 所有面板的最新输出概览
curl -H "X-API-Token: $TOKEN" http://127.0.0.1:8787/api/ai/output

# 某个面板的最新输出（text 格式）
curl -H "X-API-Token: $TOKEN" "http://127.0.0.1:8787/api/ai/output/hcmops?format=text"

# 取倒数第 2 条、原始 JSON
curl -H "X-API-Token: $TOKEN" "http://127.0.0.1:8787/api/ai/output/cf?at=-2"

# 某面板的完整历史
curl -H "X-API-Token: $TOKEN" http://127.0.0.1:8787/api/ai/output/hcm/history

# 开启 AI 输入后，把 YAML 草稿排队；用户需在应用中确认插入
curl -X POST http://127.0.0.1:8787/api/ai/input/k8s_yaml \
  -H "X-API-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"AI 草稿","text":"apiVersion: v1\nkind: ConfigMap"}'
```

已接入的数据源：云函数日志、差异对比、云函数一致性、云函数调试、Clash、HCM 对象、HCM 接口、HCM 运维、统一诊断、K8s 快照、Kibana 日志、日志、仓库。

## 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 改了代码，界面却还是老的 | **硬刷新**（**Cmd/Ctrl+Shift+R**）。后端是按请求从磁盘读前端产物的，所以重新构建后刷新即可，不用重启。 |
| 提示「会话已失效」，或文件树一片空白 | Jira Cookie 过期了。更新 `.env` 里的 `cookie`，或改用 PAT 模式。 |
| 文件预览报「文件过大或为二进制」 | Cookie 模式下大文件 / 二进制属于预期情况。改从文件树里下载，或用 PAT 模式。 |
| 批量合并卡在大文件上 | 大文件 / 二进制现在会走插件原始文件端点合并。如果仍失败，请改用 PAT 模式。 |
| 文件显示「已修改」，但内容看着一样 | 通常是行尾差异。差异对比页默认勾选「忽略行尾差异」，取消勾选就能看到它们。 |
| 打包后的应用行为和源码不一致 | 冻结的后端是旧的，需要重建 —— 见下方「给开发者」。 |
| 同名仓库，本地目录自动填充填错了 | 已知问题：`.env` 的 `MERGE_REPO_*` 映射是按仓库**名**建立的。请用下拉里显示的 ID 选对仓库，并手动指定本地目录。 |

## 各标签页速览

侧栏按使用频率做了两层组织：**常用页签平铺**（可用 `Cmd/Ctrl+1..6` 直达），其余按域收进三个可折叠分组（点击组头折叠/展开；组内有激活页签时自动展开）。Electron 下所有页签同时挂在原生菜单。

**平铺页签：**

- **仓库 / 文件树 / 文件预览** —— 选仓库、浏览、看代码。
- **差异对比** —— 上面那套对比与合并流程。
- **云函数日志** —— 云函数日志查询、导出与错误诊断（结构化过滤、实时流）。
- **K8s** —— 快照 / Pod YAML / 描述 / 网络检测 / 事件流 / 资源 Top / Shell / 文件 / 日志查看。
- **Kibana 日志** —— 查询采集进 Elasticsearch 的系统/容器日志（按服务器或 Kibana 站点）。
- **统一诊断** —— CF + K8s + dynamic_log 一键联合诊断，产出可直接喂给 AI 的证据包。

**云函数分组：**

- **云函数调试** —— 本地断点运行云函数 / mock 数据 / 按源码定位报错。
- **云函数一致性** —— 本地与线上部署版本漂移扫描。
- **Clash 分流** —— 管理代理：网卡、规则、一键应用/撤销、诊断。

**HCM 分组：**

- **HCM 对象** —— 浏览/查询 HCM 平台的数据模型（含结构化筛选）。
- **HCM 接口** —— 通用 HCM 平台 API 调试器。
- **HCM 运维** —— Redis Key 管理 / 线上错误监控 / 接口参数解密。
- **AI 数据桥** —— 把各面板输出暴露为本地 HTTP 接口供 AI 读取。

**系统分组（Electron 原生菜单 Cmd/Ctrl+Alt+1..4）：**

- **日志** —— 应用自身的运行日志，出问题时看它。
- **系统设置** —— 应用偏好设置（主题、语言、代理等）。

浅色 / 深色主题切换在顶栏；全站图标为统一设计的 SVG 单色图标（随主题与激活态着色）。

```bash
# 前端
cd frontend/web-react && npm install
npm run build        # 含类型检查；必须用它，不要直接跑 `vite build`

# 测试
QT_QPA_PLATFORM=offscreen ./venv/bin/python -m pytest tests/ --basetemp=.pytest_tmp

# 重建桌面应用实际运行的冻结后端
./venv/bin/python build/build.py --flavor backend
```

> **重要**：桌面应用运行的是**冻结后端**（`dist/jira-git-backend`）。改完 `core/` 或 `api/` 下的任何东西，都必须重建它 —— 否则应用仍跑旧逻辑，哪怕你的源码已经是最新的。这个坑真实造成过「我明明修了却没生效」的困惑。

## 已知限制

- 安装包**未签名** —— 首次打开需要手动放行。
- **Cookie 模式能力弱于 PAT** —— 部分大文件 / 二进制要走兜底通道，会话过期后浏览会失效。
- **一个 Shell 标签页对应一条会话。** 断开即结束；想同时看多个，请用全屏日志页。
- **`.env` `MERGE_REPO_*` 按仓库名建立映射** —— 同名仓库会撞 key，这类仓库请手动指定本地目录。
- PyQt6 桌面实现（原 `main.py`、`gui/`、`workers/`）已剥离至 `pyqt-legacy` 分支；主干发行版为 Electron + Tauri。
